# Known limits

- **One platform, one machine, one run.** Native Ubuntu 24.04 x86_64, resident Lean/Rust/Go toolchains and an already populated Mathlib cache. Not tested: a cold Mathlib download, a clean machine, other Linux distributions, macOS, **native Windows**, offline restoration, a person other than the publisher. `VERIFY.ps1` is a WSL2 launcher that was parsed and dry-run but not run against a working WSL2 installation.
- **Publisher-executed, not independent.** Success of `VERIFY.sh` is evidence that the encoded statements are kernel-checked by two kernels; it is not mathematical review.
- **An earlier attempt of the same entry point failed**, at the Mathlib cache restore, with `No file descriptors available` under a low open-file limit. The script now raises the limit and requires at least 8192. The recorded run is the later, complete one.
- **Encoding, not prose.** The bridge proves logical equivalence between two Lean encodings. It does not show that `Fefferman.lean` transcribes Fefferman's published prose; no independent specialist reviewed that. Formal (C) and (D) quantify over every ν > 0, which is stronger than "take ν > 0".
- **(A) and (B) are open.** Nothing here is progress on either. T-ABCD is not complete. No Clay acceptance or recognition.
- **Tools.** `nanoda_bin` rebuilt from source was byte-identical to an earlier build of the publisher's; `landrun` rebuilt from the pinned source was **not** (same module version, module hash and dependencies, different file hash), so byte-level reproducibility of `landrun` is not established. The Mathlib cache and the Lean toolchain are restored, not built from source.
- **Scope of the build.** The claimed target is the closure of `ClayStatement` (the default target). The upstream `NavierStokes` and `Euler` libraries also ship, untouched, but are **not** built or claimed beyond that closure. Seven of their modules (`Euler.EulerProof`, `Euler.GevreyComposition`, `Euler.GevreyGeneratingComposition`, `NavierStokes.AppendixHeatResults`, `NavierStokes.R3.H3Products`, `NavierStokes.R3ConvolutionYoung`, `NavierStokes.R3PressureFourier`) were observed not to compile on Lean 4.34.1 in an earlier build by the publisher; that observation is not part of the recorded run and the default target does not include them. They are port obligations. The Comparator configurations are limited to the five above.
- **The authors' Euler challenge is excluded** (`ComparatorChallenges/Euler.json`; also the S437 configuration `NavierStokes.json` is not in the verified set). Reason: the Euler challenge's import closure contains three of the seven modules above (`Euler.EulerProof`, `Euler.GevreyComposition`, `Euler.GevreyGeneratingComposition`), so it cannot be checked on Lean 4.34.1 until they are ported. It is kept in the tree unmodified and is not claimed.
- **Earlier submission S437 and the changed-file gap (scope note).** An earlier submission (S437) was released after being checked by a procedure that compared a patched tree with its reference by *changed-file list*; such a list omits files that a patch **adds**, so added files would not have been compared. S437 is **not affected**: its patch (24 files) adds no file and deletes none, so all of its proof files came from the authors' tree. The R2 package **does** add files (15 added, 24 modified relative to upstream), which is why this package ships a public source-binding check that covers added files and has a tamper self-test (`TOOLS/source_binding_check.py`). The internal lesson identifier for this note is kept in the publisher's private records and is not part of this package.
- **R3 delivered files.** The delivered R3 solution files for (C) and (D) did not compile as delivered (they never imported `NavierStokes.ComparatorSolution`, where the cited theorems live). One import line was added to each; the delivered files are kept in `R3_PACKAGES/evidence/`. No statement and no clause was changed.
- **Labels in frozen sources.** Comments in 4 files of `project/` carry internal session labels (`ClayStatement/Bridge.lean`, `ClayStatement/BridgeConverse.lean`, `ComparatorChallenges/ClayFeffermanViaD.lean`, `lakefile.toml`). They are harmless and were left unchanged to keep the verified sources frozen; the same labels appear in `SOURCE_PATCH/R2_over_upstream.patch`. No document, tool or control in this package carries one.
- **The upstream `lakefile.toml` carries duplicated comment lines** (cosmetic; unchanged).
- **Licence.** Files added by this package: the Apache-2.0 `LICENSE` at the repository root. Upstream files keep their own licence (`project/LICENSE`, Apache-2.0).
