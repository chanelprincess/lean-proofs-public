## 5. Restoration procedure
`RESTORE_AND_VERIFY.md` (in the package) gives four steps: install the toolchain; `lake exe cache get` (do not run `lake update`); build the verification tools with the same toolchain at the recorded revisions and "place landrun and nanoda_bin on PATH"; run `lake exe comparator ComparatorChallenges/NavierStokes.json`. That document does not say where `nanoda_bin` and `landrun` come from. Supplement (from the S410 phase-A script, not yet folded into the package's own file, which was left unchanged):
```
git clone https://github.com/robsimmons/nanoda_lib src/nanoda_lib
cd src/nanoda_lib && git checkout 68d5ca9db226849b41a6fff59d796ff19d0a8840 && cargo build --release   # target/release/nanoda_bin
GOBIN=<dir> go install github.com/zouuup/landrun/cmd/landrun@5ed4a3db3a4ad930d577215c6b9abaa19df7f99f
```
Network access is needed for restoration (the S425 report records the estate's standing laws against HTTPS and hashing and names the corridor's external fetch as a violation class; this package neither adds nor resolves that).
